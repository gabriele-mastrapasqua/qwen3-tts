## Hypothesis

Replacing the decoder pre-upsample f32 transformer/projection weight stream with
persistent BF16 weights and BF16 matmat could reduce decoder residency and reduce the
CP cache/overlap tax. The path was diagnostic and default-off:
`QWEN_SD_BF16_PREUP=0/1`.

The enabled path allocated approximately 44.0 MB of persistent BF16 weight copies.
The existing f32 path remained unchanged with the flag off.

## Gates

Local portable build, self-test, dispatch map, flag registry, profile validation,
`check_plan`, and `git diff --check` passed. Remote AVX512/BF16 clean build,
`--caps`, `--self-test`, `--dispatch-map`, and strict profile preflight passed.

The first paired deterministic 1.7B CLI comparison used the same model, Ryan voice,
English, seed 123, temperature 0, and stream chunk 4. Both WAVs were 10.56 s and
structurally valid. The current-generation audio comparison returned:

```
mel_corr = 0.97890 < 0.98
duration = 10.56 s vs 10.56 s
```

This is a same-generation paired failure, not a legacy golden/librosa gate. Three
additional pairs (short, conversational, medium) produced valid equal-duration WAVs;
the official comparison harness could not run for those pairs because the local
librosa/numba environment is broken. They are therefore not quality passes.

## Server C12 screen

Sequential three-wave screen, same product profile, 4x8, cap4, C12, q4, per-item
INT8 VNNI decoder, classes short/conversational/medium, no profiler/census:

| arm | STREAM p50/p95 | TOTAL p50/p95 | TTFA p50/p95 ms | prebuffer p95 ms | safe-start p95 ms | max-gap p95 ms | req/s | errors/rejects/timeouts |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| BF16 off | 0.800 / 0.842 | 0.844 / 0.951 | 245 / 273 | 276.4 | 492.2 | 322.0 | 2.02 | 0 / 0 / 0 |
| BF16 on | 0.780 / 0.825 | 0.823 / 0.935 | 236 / 265 | 249.7 | 457.3 | 316.1 | 2.08 | 0 / 0 / 0 |

Per-class STREAM p95 (off -> on): short `.843 -> .829`, conversational
`.817 -> .793`, medium `.814 -> .798`. Fixed stalls at 250/500 ms were zero in
both arms and receive coalescing was zero. This is a modest bounded-screen movement,
not a qualification result; it is not sufficient to override the quality failure.

## Fixed-B3 diagnostic

The diagnostic used `QWEN_COST_MAP=1,QWEN_STAGE_TRACE=1`, 1x8, cap3, long inputs.
It did not produce a clean sustained B3-only comparison: occupancy was

```
B1=711 (39.4%), B2=285 (15.8%), B3=810 (44.9%)
```

For the repeated active=2 decoder calls, representative stage rows were:

| arm | decoder ms | CP ms | Talker ms | wall ms |
|---|---:|---:|---:|---:|
| BF16 off | ~56.4 | ~5.1–5.5 | ~14–15 | ~75.6–77.1 |
| BF16 on | ~56.0 | ~6.0–6.2 | ~15–15.6 | ~77.4–78.1 |

The aggregate diagnostic summaries were speech decode+embed `26355 ms` off versus
`26062 ms` on over the run, with Talker `23482 ms` versus `23321 ms`. The difference
is small and the enabled arm did not reduce the observed CP time. This does not prove
that BF16 cannot reduce the intended f32 stream under a clean fixed-B experiment, but
it does not support a CP-overlap win here.

## Verdict

**NO-GO for promotion.** The BF16 pre-up path is a real, dispatch-visible diagnostic
implementation and the server screen moved modestly, but the paired same-generation
audio gate failed and the diagnostic did not establish a decoder-residency or CP-tax
reduction. Keep `QWEN_SD_BF16_PREUP` default-off; do not run a soak or make it part of
the Turin product profile.

The next single C12-WIN target is the semantics-preserving ConvT one-GEMM/repacked
geometry experiment. It should first be microbenchmarked and then screened only if it
shows a real decoder-unit reduction. Do not stack it with BF16 or scheduler changes.
